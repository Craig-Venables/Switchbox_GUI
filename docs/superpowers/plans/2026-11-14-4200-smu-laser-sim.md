# 4200 SMU + laser simulator

> **For agentic workers:** Implement task-by-task. Do not commit. Simulator only — never open GPIB, VISA, or serial.

**Goal:** Pulse GUI can run 4200 SMU electrical pulse tests and the optical laser tests against simulators, with mild real-world hiccups, before tomorrow's measurements.

**Architecture:** `KXCIClient` treats a `SIM::` address as an in-process `Simulation4200` (no pyvisa). A `keithley4200_smu_sim` profile selects that path. A `SimulatedOxxius` laser shares `Equipment/Laser_Controller/sim_link.py` with the SMU so laser-on current rises. Existing opt-in `Simulation4200Faults` stay off unless a test asks. Live hiccups are a separate flag, on for the GUI sim and off in pytest.

**Tech stack:** Python 3.10+, pytest, ruff. No PMU.

## Global constraints

- Never open GPIB/VISA/serial. Sim connect must not import a live resource manager.
- Do not commit.
- GUI widget layout positions stay as they are. Adding a dropdown entry is allowed.
- Pytest stays fast: tests pass `live_hiccups=False` and `wall_sleep=False` except one short realtime optical test.
- Follow `ruff.toml`.

## Tasks

1. **SMU pulse + sim profile** — `Simulation4200` pulse EX returns ohms for `SMU_pulse_measure` and `0` for `SMU_pulse_only`. `KXCIClient` SIM backend. `keithley4200_smu_sim` in the pulse GUI. `run_bias_timed_read` uses the sim on a SIM address. Photocurrent from `get_laser_link()`.
2. **Laser simulator** — `SimulatedOxxius` matches the Oxxius methods the pulse GUI calls. Port `SIM` connects it and updates `sim_link`. No serial.
3. **Together** — short optical run: SMU sim samples while the laser sim pulses; current is higher while the laser is on; a hiccup does not crash the run.
